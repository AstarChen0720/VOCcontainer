# VOCReviewer

這個網站要做什麼？
- 建立個人單字卡
- 點擊單字顯示字典
- 可看到別人對單字的註解

有哪些畫面？
- 左側：單字卡
- 右側：單字詳細資訊 + 塗鴉牆

有哪些資料？
- 使用者
- 單字
- 單字註解（全球共用）

資料從哪來？
- 使用者輸入或導入
- 字典 API
- Supabase

你這兩個問題其實**問得非常到位**，而且顯示你現在已經不是「新手亂學」，而是在**往「真的做得出東西」的階段走**了 👍
我會分成兩大塊回答你，而且會直接用**實務導向**的方式講，不抽象。

# 二、「架構」是什麼？我需不需要先做？

## 先一句話說清楚：

> **架構不是要你畫超複雜 UML 圖**
>
> 對你現在來說，架構就是：
> **「我知道這個網站大致由哪些部分組成，資料怎麼流」**

---

## ❌ 不需要的東西（現在）

* 完整系統設計圖
* 資料庫 ERD 細到欄位
* 設計模式大全

這些現在做 = **拖慢你**

---

## ✅ 你「一定要有」的最小架構（MVP 等級）

我幫你用**人話版架構**整理一次 👇

---

## 🧠 你的網站「最小可行架構」

### 1️⃣ 前端（React + TS + Vite）

**負責：**

* 顯示單字卡
* 點選單字 → 顯示右側字典
* 登入 / 登出
* 塗鴉牆畫面

**你現在只需要知道：**

```txt
UI（畫面）
↓
使用者操作
↓
呼叫 Supabase API
↓
顯示結果
```

---

### 2️⃣ 後端（Supabase）

**負責：**

* 使用者帳號
* 每個人自己的單字
* 全世界共用的塗鴉牆資料
* 字典查詢紀錄（未來）

你不用寫後端程式，只要：

* 設表
* 呼叫 API

---

### 3️⃣ 外部字典 API（之後）

**負責：**

* 日文單字解釋
* 發音、例句

---

## ✅ 建議開發順序（非常重要）

### 🟢 Phase 0：專案啟動（1 天）

* Vite + React + TS 建好
* 畫面切左右
* 假資料顯示單字卡

👉 **不接後端、不登入、不字典**

---

### 🟢 Phase 1：單字卡 CRUD（2–3 天）

* 新增單字
* 顯示單字卡
* 點選單字顯示右側（先假資料）

👉 **這步完成 = 你已經「做出一個東西」**

---

### 🟢 Phase 2：Supabase（帳號 + 資料分離）（2 天）

* Email 登入
* 每人只看到自己的單字

👉 這一步完成，你的產品「突然變得很真」

---

### 🟢 Phase 3：字典 API（1–2 天）

* 點選單字 → 查 API
* 顯示解釋 / 例句

---

### 🟢 Phase 4：全球塗鴉牆（進階）

* 每個單字有共用留言
* 可文字 / 圖片

---

### 🔵 Phase 5（未來）

* 每日目標
* Chrome Extension
